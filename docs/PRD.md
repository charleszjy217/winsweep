# PRD：WinSweep — Windows 垃圾检测与安全清理工具

## 0. 项目信息

| 项 | 内容 |
|---|---|
| 产品名称 | WinSweep（暂定，可改） |
| Language | 简体中文 |
| 技术栈 | Tauri v2（Rust 后端 + 原生 Web 前端），前端建议 Vite + React + Tailwind CSS |
| 目标平台 | Windows 10 / 11（x64） |
| 交付形态 | 独立桌面软件，编译为单个 `.exe`（发布安装包 + 便携版） |
| exe 体积目标 | ≤ 15 MB（Release，UPX 可选） |
| 文档类型 | 简单 PRD（MVP 可发布范围） |

### 原始需求复述

用户希望有一个能**实时监测 / 扫描 Windows 系统垃圾数据并安全清理**的桌面软件，最终编译为体积小巧的 `.exe` 并可对外发布。软件需覆盖回收站、系统 / 用户临时目录、Windows 更新缓存、各类开发缓存（pip / npm / .gradle 等）等无用数据，界面要美观且具备「程序员风格」（暗色主题、等宽字体、终端 / 极客气质）。

用户列举的当前占用示例：

| 类别 | 示例占用 |
|---|---|
| 回收站 | 0.85 GB |
| 用户临时目录 | 1.12 GB |
| 系统临时目录 | 0.01 GB |
| Windows 更新缓存 | 0 GB |
| pip 缓存 | 3.22 GB |
| npm 缓存 | 2.92 GB |
| .gradle 缓存 | 3.63 GB |
| 其他无用数据 | … |

### 已确认的关键决策（来自用户）

1. **技术栈 / 体积**：Tauri v2（Rust + 原生 Web 前端），exe ≤ 15 MB。
2. **扫描方式**：手动扫描 + 实时文件监控**两者都要**；实时监控可开关，**默认关闭**以省资源。
3. **清理策略**：两种模式可选 —「移入系统回收站（可恢复）」与「永久删除（不可恢复）」；**必须带预览 + 二次确认，绝不误删**。
4. **形态**：独立桌面软件（非浏览器插件），可发布。

## 1. 产品目标

**一句话定位**：WinSweep 是一款面向开发者和 Windows 高级用户的、极客风的系统垃圾扫描与安全清理工具——**扫得全、看得清、删得稳**。

**核心价值**：
- **扫得全**：一站式覆盖系统垃圾 + 开发工具链缓存（pip / npm / gradle / m2 / cargo / go）。
- **看得清**：扫描结果按类别列大小、可逐项勾选、清理前全量预览。
- **删得稳**：回收站兜底 + 二次确认 + 黑名单保护，从机制上杜绝误删。

**三个正交目标**：
1. **安全第一**：任何清理动作都可逆或需显式确认，误删率目标 = 0。
2. **省心高效**：一次扫描给出全盘垃圾视图，一键清理释放 GB 级空间（如示例中约 11 GB+）。
3. **极客体验**：暗色终端风界面 + 实时监控，契合目标人群审美与工作流。

## 2. 目标用户与场景

| 用户群 | 特征 | 核心诉求 |
|---|---|---|
| **开发者 / 程序员（主力）** | 常装多套工具链，pip/npm/gradle 缓存动辄数 GB | 快速定位并清理开发缓存，且不想破坏依赖完整性 |
| **Windows 高级用户 / 折腾党** | 关注 C 盘空间、系统优化 | 清理系统临时文件、更新缓存、转储文件 |
| **普通 PC 用户** | C 盘告急但不识路径 | 低门槛一键清理，且**害怕误删** |
| **测试 / 运维人员** | 需要在多机批量清理 | 可发布、可复用的独立工具 |

**典型场景**：
- 场景 A：C 盘红了，用户打开软件 → 一键扫描 → 看到 pip(3.2G)+npm(2.9G)+gradle(3.6G) → 勾选后清理 → 秒回 9GB+。
- 场景 B：开发者想一边写代码一边自动清临时产物 → 开启实时监控 → 后台静默清理 `%TEMP%` 新产生的碎片。
- 场景 C：用户不确定某文件能否删 → 先「预览」看清清单 → 选择「移入回收站」→ 后悔了可从回收站还原。

## 3. 用户故事

1. 作为**开发者**，我希望扫描能覆盖 pip / npm / yarn / .gradle / .m2 / cargo / go build 等缓存，以便一次性释放被开发工具占用的数 GB 空间。
2. 作为**普通用户**，我希望清理前能看到「将被删除的文件清单 + 总大小」，以便在动手前确认没有重要文件。
3. 作为**谨慎的用户**，我希望清理时可以选择「移入回收站」而非直接删除，以便误删后还能恢复。
4. 作为**高级用户**，我希望软件能识别系统关键组件并标为「高风险」并默认不勾选，以便我不会因为手滑删掉系统文件。
5. 作为**追求性能的用户**，我希望可以手动触发全盘扫描，以便在想清理时才扫描、不占用后台资源。
6. 作为**想省心的开发者**，我希望可以开启实时文件监控来自动清理新产生的临时垃圾，并且这个开关默认关闭、可随时关停，以便我能控制资源占用。
7. 作为**洁癖用户**，我希望界面是暗色、等宽字体、终端风格且显示实时进度，以便使用体验符合我的审美。
8. 作为**可发布软件的维护者 / 用户**，我希望软件是体积小巧的独立 exe，以便无需依赖运行时即可分发和运行。

## 4. 需求池

> 优先级：**P0 = 必须有（MVP 可发布）**；**P1 = 重要**；**P2 = 锦上添花**。每条需求给出可验收标准。

### P0 — MVP 必须有

| ID | 需求 | 可验收标准 |
|---|---|---|
| P0-1 | 手动全盘扫描 | 点击「扫描」后能遍历下述所有垃圾类别，返回每类占用大小与文件数；10 万文件量级扫描 < 30s |
| P0-2 | 垃圾类别覆盖（至少） | 覆盖：%TEMP%、C:\Windows\Temp、回收站、Windows 更新缓存、pip / npm / yarn / .gradle / .m2 / cargo registry / go build cache、浏览器缓存、错误报告与转储、缩略图缓存、传递优化文件、系统日志 |
| P0-3 | 结果可视化 | 主界面按类别展示：名称、大小、文件数、安全等级、勾选框；支持全选 / 反选 |
| P0-4 | 清理前预览 | 清理前弹出预览面板，列出将处理的文件路径（可滚动）+ 合计大小；不预览不清理 |
| P0-5 | 二次确认 | 执行清理前必须弹确认框（含「本操作将影响 N 个文件 / M GB」警示），用户再次确认才执行 |
| P0-6 | 双清理模式 | 提供「移入回收站」与「永久删除」两种模式，清理前可选；默认选中「移入回收站」 |
| P0-7 | 受保护路径黑名单 | 内置黑名单（系统目录、正在使用的系统组件等），黑名单内文件永不进入可删列表 |
| P0-8 | 占用中文件跳过 | 遇到被占用 / 无权限文件时跳过并在报告中标明，不中断整体清理 |
| P0-9 | 安全等级分类 | 每类垃圾标注「低风险 / 中风险 / 高风险」，高风险默认不勾选，需额外警示 |
| P0-10 | 清理结果报告 | 清理后展示：释放空间、成功 / 跳过 / 失败数量及原因 |
| P0-11 | 极客风暗色 UI | 暗色主题、等宽字体、终端气质；符合第 5 节视觉规范 |
| P0-12 | 独立 exe 发布 | 编译产出单文件 exe，体积 ≤ 15 MB，无需外部运行时即可在 Windows 10/11 运行 |

### P1 — 重要

| ID | 需求 | 可验收标准 |
|---|---|---|

## 6. 安全与合规设计（「绝不误删」机制）

| 机制 | 说明 |
|---|---|
| **① 预览清单** | 任何清理前必须生成完整清单（路径 + 大小），用户可见、可搜索、可导出；不预览不可执行 |
| **② 二次确认** | 弹窗明确告知影响范围（类别数 / 文件数 / 大小 / 模式），需再次点击确认 |
| **③ 回收站兜底** | 默认模式为「移入系统回收站」，可一键从回收站还原；仅用户显式选择「永久删除」+ 额外确认才不可逆 |
| **④ 受保护路径黑名单** | 内置不可删除白名单：`C:\Windows\System32`、`C:\Windows\SysWOW64`、`C:\Program Files*`、`C:\ProgramData\Microsoft\Windows`、注册表相关、引导卷系统目录等；黑名单优先级最高，命中即从可删列表剔除 |
| **⑤ 占用中文件跳过** | 通过尝试独占打开 / 系统 API 判断占用，被占用或无权限的文件自动跳过并记入报告，不强制删除 |
| **⑥ dry-run 模式** | 「模拟清理」仅生成报告，零文件改动，供用户先验证效果 |
| **⑦ 高风险类别隔离** | 系统日志、系统组件等标记为高风险，默认不勾选，勾选时二次警示 |
| **⑧ 实时监控禁止永久删除** | 后台自动清理仅允许「提醒」或「移入回收站」，杜绝静默不可逆删除 |
| **⑨ 操作日志** | 记录每次清理的时间、类别、模式、数量、结果，支持审计与回溯 |
| **⑩ 最小权限** | 默认以普通权限运行；仅当用户明确需要清理系统级目录时才提示以管理员权限重启，且在高风险操作前再次确认 |

## 7. 待确认问题

1. **产品命名**：「WinSweep」是否可接受？是否需中文名（如「净界 / 清道夫」）？
2. **是否需要管理员权限**：系统临时目录 / 更新缓存 / 传递优化文件清理需管理员权限，是否接受「普通权限为主 + 按需提权」的方案？
3. **浏览器缓存范围**：默认清理主流浏览器（Chrome/Edge/Firefox）缓存的哪一部分？是否需要「仅缓存、不动 Cookie / 登录态」的强约束？
4. **实时监控默认目录**：默认监控哪些目录（仅 `%TEMP%`，还是包含自定义）？触发提醒的频率上限？
5. **发布渠道与签名**：是否需要代码签名证书 / 安装包（MSI/NSIS）？还是先出便携版 exe？
6. **P2 取舍**：定时任务、CLI、托盘常驻中，哪些希望进入首个发布版本？
7. **语言范围**：首版是否仅简体中文，还是需预留多语言？
